---
name: coverage-analysis
description: Find meaningful untested Python branches, improve regression coverage, or interpret full and changed-line coverage failures.
---

Read [quality](../../../docs/QUALITY.md). Discover the destination project's coverage command and inspect its reports only for affected modules. Rank gaps by failure impact: authorization, validation, error mapping, retries, timeouts, cancellation and persistence.

Write tests for observable outcomes. Exercise success and failure paths with realistic boundary inputs; use real local databases and protocol clients where inexpensive. Fake paid models and external services at their adapter boundary. Verify mocks do not merely repeat the implementation.

Respect the destination project's agreed full and changed-code thresholds, with branch measurement where supported. Establish a committed comparison base before reporting changed-code coverage. A missing base is a setup error, not a pass. The toolkit's own 90% maintenance gate is not automatically installed in user projects.

Never inflate the percentage by excluding hard code, adding assertions without meaning or accepting skipped integration tests as validation. Report coverage scope, gaps and live tests not run.
